Problems today

Six issues found across the shipped UI. All of them resolved in the new design system.

→
1. Five chips per panel → one cycle button
Five big chips (All P1..P4) were eating space in every panel. Replaced by a single 2×2 dot button that cycles through players — photographic memory across the whole app.
2. Playback bars disagree between players
P1, P2, P3 each shipped a different set of icons and heights. Bars normalized to one template: every player gets the same buttons in the same order, always.
3. Loud destructive action
Big red button permanently shown. Moved into an overflow menu with a confirmation modal.
4. Inconsistent button sizes
Four button base classes drift over time. Replaced by one .btn primitive.

Icon strategy — how to keep the library coherent

The app already ships 100+ Streamline Core SVGs in /Icons/. Policy: pick from this set first; never mix stroke weights, never mix filled + outline in the same view. When something is missing, extend ICON_MAP in index.html — don't drop an emoji.

Decision flow

  1. Exists in /Icons/? — use it via icon('name').
  2. Missing but Streamline has it? — drop the SVG into /Icons/, add an entry to ICON_MAP, recolor with currentColor.
  3. Brand new concept? — sketch in Streamline style (1.75 stroke, rounded caps/joins, 24×24 viewBox, outline). Add to /Icons/ and MAP. No emoji.
  4. Filled variants only for CTAs (primary button, play button, download active). Everywhere else: outline.

Rules

  • Stroke width: 1.75 · caps: round · joins: round.
  • ViewBox: 24×24. Rendered sizes: 12 / 16 / 22 (sm / md / lg).
  • Color: currentColor. Never hard-code hex in SVG.
  • Action icons follow verb semantics: action = outline, status = filled.
  • One icon per concept, across the whole app. If "delete" is a trash can in Tags, it's a trash can in Cronologia too.
